# 诊断修复与12小时记录

版本：13.0-rc6-plq110.4（包含前序诊断修复）。

主界面菜单“开始12小时诊断”通过现有经过来源认证的配置通道开启，默认关闭，可提前停止。重启后仍使用原墙上时间到期点；同一次运行使用单调时钟，重复加载相同配置不会延长会话。系统时间在重启前被大幅修改时，应重新确认到期时间。

系统框架异步写入 `/data/system/fcmfix-coloros/night-{previous,current}.log`，每个256KB；目录和文件限所有者访问。日志包含会话ID、墙上时间、开机后单调时间和模块日志，不读取聊天消息正文。不设置唤醒闹钟或 wakelock；采样空档明确表示未知。写入受限、异常或256项队列满时，自查会提示；不能把开启配置等同于已可靠记录。导出报告会收集现存日志。

Hook页面的“已注册”仅描述安装结果；回调次数和保护/适配动作描述观察到的执行，不保证通知送达。参数修改、返回值修改和解冻动作的统计不同于消息数量；零动作可能只是相关场景未发生。累计异常保留到对应进程重启，暂缺实例状态在后续解冻动作成功后解除。升级后加载版本不一致会提示重启。

可信投递请求计数来自广播入口，服务直接投递和GMS代理通知可能不计入。TCP候选连接和首末观察间隔均不是FCM协议健康证明。

报告完整性要求脚本完成标记、退出码0、读取线程结束且未超时；部分结果可以保留并明确标注。默认处理已知非目标包名与IP，目标应用和Google核心包保留。其他日志内容不保证匿名，原始内容可另选。

回归覆盖：超时/缺失完成标记/异常退出、日志旋转及重开、长事件/换行限制、会话到期/重启/重复配置、脱敏时保留时间与目标、Hook短路计数和异常回退。OEM实机、文件SELinux权限、通知体验和整夜稳定性需另行验证。

实机配置热更新：应用持久化递增版本号后，通过经过原有包名和UID验证的有序广播传递完整配置快照；工作线程仅接受更高版本，避免旧远程缓存覆盖新设置。自查额外比较版本与诊断截止时间。远程偏好用于开机读取和缓存监听；来源/用户校验保持原行为。

实机Root无法直接读取私有日志时，报告通过认证系统框架查询附加每文件末尾32KB；读取在后台线程由文件所属进程执行，不放宽权限或SELinux策略。结果明确标记尾部和截断，不能当作整个256KB文件。每进程内存日志也限制为32768字符，以控制Binder传输大小。
